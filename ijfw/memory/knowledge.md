Fixed the concurrent rescan race in bookmark/shared/scan-controller.js. A user-triggered scan-now during an in-flight scan could let a stale async storage write overwrite the new scan's queue/checkpoint/records/report. Chose the controller-local single-flight promise approach (the preferred option). createScanController now keeps a closure-local `operationTail` promise; a `serialize(fn)` wrapper routes the three public drivers (startNewScan, resume, processActiveWindow) through it so no two bodies overlap and every stale storage write is flushed before the next operation begins. Added deterministic harness Part 5: starts scan A against tree A with a gated first storage write held in-flight, invokes startNewScan (tree B, pruned) mid-write on the SAME controller, releases the gate, then asserts final records/report/count == only tree B and no stale record from A lingers. `node test/run-tests.js 3000 42` all pass. Bookmark extension M1/2 stabilization: fixed repeated "Scan now" clicking causing repeated rescans/looping. Root cause: the controller already had a single-flight serialize() guard against overlapping/write-corrupting rescans (no stale-write overwrite), but it serializes+queues rather than dedupes, so repeated popup clicks sent a scan-now message per click and each queued a full rescan (restart-from-scratch) = loop. Fix is UI event/state + a controller-level defense-in-depth driver: (1) popup.js disables the Scan now button during SCANNING and while a request is pending, dedupes requestScan by re-entry + checkpoint-phase check, seeds the disabled state at init, and re-enables on storage change to non-SCANNING; added CSS .br-scan-btn:disabled. (2) scan-controller.js gains a new serialized public driver requestScan() that reads the checkpoint and, while phase===SCANNING, returns {skipped:true} without restarting (once DONE a later request starts a fresh scan). (3) service-worker.js 'scan-now' routes through controller.requestScan() (not startNewScan) and returns {ok, skipped}. startNewScan remains for install-time/forced rescans and unchanged. Regression test = harness Part 11: seeds a SCANNING mid-scan checkpoint, fires a burst of 4 rapid requestScan calls, asserts all skipped, persisted storage bit-identical across the burst (no overlapping reset), then drives to DONE and asserts a post-completion requestScan starts a fresh scan normally. node test/run-tests.js 3000 42 ALL PASS. Playwright browser NOT used; manual verification recommended: load unpacked, start a large scan, confirm Scan now is disabled/grayed and rapid clicks do not restart or queue scans, and that it re-enables on completion.

**Why:** A real scan spans many worker wakes held in storage as SCANNING; while SCANNING, a naive popup let each click queue another full rescan. The controller single-flight serialized but did not dedupe, so rapid clicks amplified into a rescan loop.

**How to apply:** The popup disables Scan now during SCANNING/pending; worker scan-now uses requestScan() which skips starting a new scan while the persisted checkpoint is SCANNING. Only restart on a genuinely running scan, never overlap.
